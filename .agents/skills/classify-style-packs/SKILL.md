# Art Canvas 风格包分类

## 权威资料

以本 Skill 所在项目为根定位文件，不依赖机器盘符，也不要复制另一套分类字典。

- 开始分类前读取 [详细分类表](../../../docs/style-pack-taxonomy-v1.md)：标准大类、子类 ID、标签、归类边界、旧分类映射。
- 制作或修改包前读取 [数据与分类规范](../../../docs/style-pack-spec-v1.md)：真实文件结构、示例、字段、计数、迁移和回滚要求。
- 资料缺失或版本冲突时先报告，仍可只读盘点；不能自行编造一套分类后写入包。

两份文档当前为 v1.1 建议稿，本 Skill 采用它们作为此次任务的分类基线，不代表历史数据已迁移或程序已实现所有目标校验。更新分类标准属于另一项明确变更，不在普通分类任务中顺手修改字典。

## 确定任务范围

根据用户要求选择产物，不因调用 Skill 自动扩大授权：

- **盘点／建议**：只读原包，输出分类建议和问题清单。
- **执行分类／整理包**：在独立输出目录生成新版包和报告，保留原包。
- **安装／替换当前包**：只有会话已明确要求这一步时执行；先完成可检查产物、备份与校验。已有授权直接继续，没有授权则交付生成的包，不替换正在使用的数据。

本 Skill 本身不授权下载、付费模型调用、修改工具代码、删除素材、重启服务或改写所有已安装包。默认沿用当前 AI 能力阅读分类，不为分类擅自调用外部服务。

## 理解本项目的数据

优先确认输入是原包目录、ZIP，还是正在使用的安装包，范围只限用户指定的数据。

- 发布包在本仓库 `packs/<packId>/`，结构为 `pack.json` 加分类 JSON，内容结构是 `categories → subcategories → presets`。
- 原始完整数据在本地 `data/style-packs-source/`；下载缓存与分类报告在 `artifacts/`，默认不进 Git。不要把历史报告中的旧绝对路径当作当前输出位置。
- 默认从指定的原始目录或平台包生成独立分类目录，不直接覆盖 `packs/`，不读取或写入 Art Canvas 用户库。安装与用户增量层由主工具负责，参见独立仓库 README 的消费说明。
- 按原始文件遍历完整条目，不能仅分类界面当前加载的第一页；核对全局 ID，跨包冲突不靠加载顺序覆盖。
- 标题关键词推断的 `photography-*` 是临时展示分组，不是审核后的分类。正式目标 ID 使用分类表中的 `photography_*`。

## 分阶段批量分类（默认执行方式）

### 先运行本地规则脚本（不调用 AI）

项目已提供 `scripts/title_classify.py`、标题规则 `scripts/title_rules.json` 和正文规则 `scripts/content_rules.json`。默认先处理标题，未解决项再走本地正文辅助规则，最后才把剩余队列交给 AI；不发送网络请求，也不读取图片或调用模型。

在项目根目录执行：

```powershell
python -X utf8 .agents/skills/classify-style-packs/scripts/title_classify.py --input "packs/platform-chatgpt" --output "artifacts/title-classification/批次名" --write-files
```

支持多个 ZIP 或包目录输入；默认不改输入。用户要求先整理提示词文件时，使用 `--write-files`：在 `输出目录/classified/<packId>/` 写出按大类和子类重组后的 JSON 与清单，不生成 ZIP、不安装。正文、ID、图片地址和未知扩展字段不变，未确定项写入对应 pending 分类，不能称为全部已确认。已有输出目录拒绝覆盖，避免丢失后续人工编辑；需要重生成时选新批次目录。

用户后续明确要求打包时才用 `--write-packs`；输入可以是上述整理后的目录，人工或 AI 编辑的分类应带相应审核元数据以便保留。不要默认把 JSON 整理与 ZIP 打包绑在一起。仅报告的重复运行会复用未变化条目的结果。

`--title-only` 可关闭正文辅助，只做标题初筛；`--content-rules` 可指定正文规则文件。模式、标题／正文、规则及引擎版本均参与缓存签名，切换模式不会复用不匹配的结果。

- `assignments.jsonl`：逐条规则证据、建议、摘要、阶段及缓存信息。
- `pending-titles.jsonl`：经过本地标题及正文规则后仍未解决的短标题清单；仅标题模式下则是标题初筛剩余项。
- `pending-content.jsonl`：同一未解决队列及完整正文，第二阶段按记录键选择性读取，不整份倾倒进上下文。
- `summary.json`：标题初筛和最终结果分别统计，包含正文处理数、正文新增完整分类数、相同正文复用数、缓存命中、运行耗时、冲突及生成包路径。

标题规则先补齐中英文同义表达，再按字典中的明确交付物优先关系消解媒介冲突，例如水彩海报归商业设计、动漫角色三维渲染归数字 3D。只有消解后唯一大类、唯一子类命中时给明确建议；子类仍冲突进大类待细分，大类仍冲突进全局待分类。标题明确包含比较、混合等目的时不强行套优先级。规则结果使用 `method: rules`，不是 AI 或人工审核。

正文辅助的边界：

- 标题明确项默认跳过正文；标题大类已知的只在该类内细分，但检测到其他大类有明确正文证据时保留原大类待细分并记录冲突，不强行覆盖。
- 大类未知时，必须同时有任务词和至少一个不与任务词重叠的独立佐证，且只有一个大类成立，才继续判断子类。不因出现 woman、paper、cinematic 等单词直接定类。
- 匹配全文的正向子句，排除显式负向提示词段和含否定词的子句。这是保守规则过滤，不是自然语言完整理解；复杂引用、否定、混合任务仍可能需要复核。
- 可解析 JSON（含代码围栏或模板前缀）中的字符串 `prompt`、`positive_prompt`、`positive`、`提示词`、`正向提示词` 字段，忽略同对象的负向字段和元数据；不执行模板，不假定支持任意嵌套结构。无法解析时仍按文本保守过滤显式负向段。
- 正文多子类命中仍保留待细分，多大类命中仍保留待整理。规则给出的是建议，不以覆盖率代替准确率。
- 同一批次中，完全相同正文且大类上下文相同的计算一次；不同大类上下文不串用结果，不合并或删除条目 ID。原正文与所有非分类字段保持不变。
- 正文结果标记 `stage: content` 并记录证据，不能标成人工审核。原有人工审核和非本地规则的正文分类保持优先；本地规则结果在规则更新时可以重新计算。

分类字典仍以项目文档为唯一真源；规则文件只保存匹配证据，启动时校验所用 ID。新增规则后运行 `tests/test_style_title_classify.py`，真实数据先生成建议检查，再决定是否生成包。已有正文分类或人工审核结果保留；跨包同 ID 正文／分类冲突会记录并阻止生成包。

历史包中的空正文条目仍可按标题生成建议，但列入 `summary.json` 的 `invalid_items`，不静默删除或补写正文；`--write-files` 保留它们供后续整理，`--write-packs` 则阻止生成 ZIP。跨包同 ID 内容或分类冲突会阻止两种输出。某些 Fooocus 模板只有负向指令，应单独确认兼容方式，不在本脚本中擅自重写。

### 第一阶段：仅用标题初筛

程序遍历原始包并保留完整数据、计算摘要；本地规则先处理明确项，交给 AI 的剩余记录只包含记录键、条目 ID 和标题。计算正文摘要不等于把全文送进模型。首次可每批约 100 条，按实际上下文和标题长度调整；复用同一分类字典，不为每条单独启动一次分类任务。

按标题表达的主要任务／交付物判断，不能只看第一个匹配词：

| 初筛结果 | 归属 | 记录 |
|---|---|---|
| 大类和子类都明确 | 标准大类 + 对应标准子类 | `stage: title`，`resolution: resolved`，`status: suggested` |
| 大类明确、子类不确定 | 对应大类 + `<大类 ID>_pending` 待细分 | `stage: title`，`resolution: category_only`，`status: needs_review` |
| 大类也不确定、标题为空或含冲突任务 | `uncategorized` + `uncategorized_pending` | `stage: title`，`resolution: unresolved`，`status: needs_review` |

例如“窗边自然光人像摄影”可归摄影／人物肖像；“摄影实验合集”只能先归摄影／待细分；“梦境之光”先放全局待分类。分类依据记录为简短理由，不凭空补标签、推断来源或声称看过正文、图片。标题缺乏明确证据时保留待处理，比误分后全库重查更省成本。

初筛完成后立即落盘结果并汇报覆盖数、明确数、待细分数、全局待整理数。用户只要求初筛时在这里交付；要求完成分类时继续第二阶段，不额外询问已授权步骤。

### 第二阶段：只对未解决项读取正文

先由脚本对 `category_only` 和 `unresolved` 条目执行上述本地正文规则。仍未解决时，才把对应完整正文、标题及已有证据批量提供给 AI：前者重点细分子类，同时允许纠正大类；后者判断完整归属。正文较长时缩小批次，不截断正文后假称完成全文分类。

标题已明确的 `resolved` 项不默认全文重读。需要抽检时按大类抽样，记录实际样本数与发现的问题；若发现同一歧义模式，扩大检查该模式或对应批次，不无理由重跑全库。用户要求全量正文复核时遵从用户要求。

正文仍不能判断时，大类确定的保留该类 `_pending`，大类不确定的保留全局待分类，记录待处理原因。可取得的预览图仅在解决具体歧义时读取；未查看图片不能声称已经看过。`stage: content` 表示读过正文，不等于人工审核。

### 分类边界与审核

- 每条一个大类和子类；年代、光影等作标签。来源平台和系列独立记录，`yuanbao`、`fooocus_*` 不整体映射成内容类别。
- `*_pending` 是尚未确定；`*_other` 是判断后确认不属于现有子类。不能混用，也不能拿 `general` 代替待分类。
- 同 ID 副本先核对内容与归属，不靠加载顺序覆盖；不同 ID 的相似内容只标疑似重复，不自动删除。
- AI 分类使用 `method: assisted`；明确建议用 `status: suggested`，未确定或冲突用 `needs_review`。只有实际人工确认才能标 `reviewed`，保留已有人工审核结果。`resolved` 只表示当前阶段分类明确，不表示人工审核。

## 缓存与续跑

批量输出结构化 JSONL 或 JSON 后，由程序核对记录键、条目 ID、覆盖数和合法父子分类，再落盘；缺失或非法结果只重试受影响记录，不能把整批当作成功或反复提交整个数据集。

为每条保存标题、完整正文摘要、分类版本、分类规则版本和所用阶段。复用结果时：

- 同记录键、标题／正文摘要和规则版本均未变化：直接复用已有分类，不再次送给 AI。
- 标题或正文变化：只重新处理变化条目；人工审核结果存在时标记需要复核，不能静默覆盖。
- 分类字典／规则变化：先核对受影响分类，记录失效范围；能证明不受影响的保留，无法判断影响范围时标记待复核。
- 第二阶段成功结果替代初筛建议，保留阶段历史；不得因重新跑第一阶段而把正文分类降级覆盖。

批次完成就保存进度。重试仍失败的记录进问题清单，保留成功项，不无限循环。不要为了提高效率擅自切换模型或调用未授权的外部服务。

## 生成建议与新版包

先记录原包版本和每个条目的包名、文件、原大类、原子类、ID，以及原文件和内容摘要。大量数据可按原包或大类分批处理，每批使用相同分类版本，输出可续跑的记录；重复运行必须能够识别已处理的条目，不能生成新 ID 造成重复。分类结果确认后，按维护入口说明更新相应平台包与清单；不把整库结果直接覆盖所有平台包。

建议记录使用 JSONL 或 CSV，至少包含：

```text
pack_id, file, item_id, old_category, old_subcategory,
new_category, new_subcategory, tags, stage, resolution, method, status, reason,
title_hash, prompt_hash, taxonomy_version, rules_version
```

一条记录定位到原包中的一个具体条目；同 ID 跨包或跨路径出现时不能只用 ID 作报告唯一键。保留冲突和例外清单。

执行分类时：

- 在新目录重组文件和清单，标准分类以嵌套路径为唯一权威。保留原有字段，不把数据简化为展示索引字段。
- 保留 ID、完整正文、负向正文、图片地址及其他非分类内容；不能顺手翻译、润色、补写或截断。
- 规范化现有标签时保留原标签到迁移记录，不能静默丢弃未知标签；必要时待审核。
- 新增结构化来源时保留原 `description`。当前来源筛选仍依赖它，不能为了字段漂亮破坏兼容。
- 更新包版本、分类版本、清单文件登记及实际 `entryCount`；当前结构版本仍为 `schema: 1`，不要伪造未实现的 schema 2。
- 拆条、合并、去重删除、变更 ID 不属于普通重分类；只列出建议，除非用户另外要求。
- 涉及用户增量层时同步制定新增条目路径迁移方案，验证按 ID 的修改／删除仍正确；不能只改包文件留下失效覆盖。

输出目录不覆盖已有报告或包；重跑沿用明确的批次目录和进度记录，必要时创建新批次。ZIP 解包使用现有安全实现或等效路径校验，不能绕过项目导入器的安全约束。

## 必须验证的结果

对实际生成的文件执行检查，不仅凭分类建议表判断成功：

- 全部 JSON 可解析，清单登记文件存在，大类和子类 ID 及父子关系合法。
- 同包 ID 唯一；跨包重复、内容冲突和分类冲突有报告。
- 按“原包 + 条目 ID + 出现次数”核对迁移前后的多重集合；不能只比较总数。
- 对每条保留字段核对正文、负向正文、图片地址和未知扩展字段；只允许预期的分类／标签／来源补充／审核元数据变化。
- 子类计数之和等于大类数，包计数等于清单实际数；安装声明总数和合并有效数分开报告。
- 分类建议覆盖全部输入条目，没有无记录跳过、静默删除或意外新增。
- 分别统计标题初筛明确、正文细分完成、待细分、全局待整理、缓存复用和失败数量；同一条目的历史阶段不能重复算为多条成品。
- 对具体争议、其他类、待分类条目有列表；人工复核和自动检查分开陈述。

仅生成文档或建议时不必启动服务、跑全套测试或请求真实生图。替换当前使用的数据时，再按影响验证详情、来源筛选、收藏引用和缓存刷新；无法实测的部分如实注明。

## 简短交付

提供新版包／建议报告／冲突清单的真实路径，说明处理条数、待审核条数、完整性核对结果，以及是否修改了正在使用的数据。若已替换，提供原包和增量层备份位置；不要声称未实现的标签 UI 或严格导入校验已经生效。
