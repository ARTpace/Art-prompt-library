# CCPrompt 提示词下载与风格包

脚本：`tools/ccprompt_download.py`，仅使用 Python 标准库。采集网站画廊公开图片列表和逐条详情；不采集视频、不读取账户凭据、不自动安装或替换现有风格包。

## 使用

在项目根目录执行：

```powershell
# 小批量验证
python -X utf8 tools/ccprompt_download.py download --limit 36

# 全量采集；再次执行相同命令会使用已有分页和详情缓存续跑，并重试失败条目
python -X utf8 tools/ccprompt_download.py download

# 查看进度
python -X utf8 tools/ccprompt_download.py status

# 不请求网络，用已下载的详情重新打包
python -X utf8 tools/ccprompt_download.py build
```

默认输出为 `artifacts/ccprompt/`，已经由项目 artifacts 忽略规则排除提交。`--output` 可指定其他批次目录；`--workers` 默认 4，范围 1–8；`--delay` 为每次请求前的间隔，默认 0.15 秒；`--pack-size` 默认每包 3,000 条。

`--limit` 限制本次范围，不删除已有数据；打包包含当前目录所有成功下载条目。需要一个完全独立的样本时指定新的 `--output`。同一个输出目录不要同时启动多个下载或打包进程。

## 输出

- `source.sqlite3`：原始分页、完整详情、错误记录，是断点续传及无损核对的数据源。
- `packs/ccprompt-images-001.zip` 等：可在提示词库的风格包管理中导入，每包最多 3,000 条，避免单包过大。
- `report.json`：当前打包数量、各包 SHA-256、失败 ID、全量完成状态。
- `progress.json`：下载中周期更新的进度快照；实时进度也会输出到控制台。

列表只有缩略字段，正文必须调用逐条详情接口；网站实际分页大小可能不同于请求值，脚本读取服务器返回的 `pageSize`。全量任务可能耗时较长，不能把只拿到列表的数量称为已下载提示词数。

每个详情保留原始正文、标题、原作者、网站详情链接、网站标签及完整 `source_metadata`，其中包括网站提供的双语内容与解析。原始正文不改写、不截断。相同原始 ID 生成稳定 `ccprompt_` 前缀 ID；不同 ID 的相似内容不自动删除。

预览图片仅保存远程地址，不下载图片二进制；因此风格包不是离线图片包，图片可用性依赖原站。脚本只承诺保存公开返回的内容，遇到缺失或受限内容会记录或停止，不生成虚假的正文。

## 分类与导入

网站列表不提供项目标准的两级分类。采集包统一放在 `待分类 → 待人工判断`，保留网站原标签；这不是已完成语义分类的发布包。

后续使用 `.agents/skills/classify-style-packs/SKILL.md`，读取完整提示词，按项目分类表整理新版包；不能把关键词猜测伪装成人工审核。生成的采集包不自动导入，避免把上万条待分类内容直接混入现有库。

增量采集不等于续跑：本脚本续跑同一列表快照。重新获取网站新增内容时使用新的 `--output` 批次目录，再按稳定 ID 核对。网站在采集中更新导致分页总数变化时停止并保留缓存；即使总数未变化，分页顺序也可能漂移，`report.complete` 会核对实际唯一 ID 数量，不能证明网站从未变动。

访问限制时停止，不绕过登录或站点限制。临时网络错误及 429/5xx 有限重试；失败可通过原命令续跑。异常退出仍会尝试打包成功下载的部分；只有 `report.json` 的 `complete: true` 才表示列表计数、详情和失败检查均完成，部分包不能称为全量。

脚本在同一输出批次里原子更新 ZIP 和报告，方便恢复任务；需要保留某次中间产物时先另存。不要在下载尚未结束时安装中间包后又把它当作固定版本发布。

## 验证

```powershell
python -m unittest discover -s tests -p test_ccprompt_download.py
```

测试覆盖正文和来源无损保留、生成 ZIP 内容及清单、分包计数、缓存续跑、失败报告和视频排除；不依赖 Art Canvas 源码，不访问网站或写入用户正在使用的包目录。
